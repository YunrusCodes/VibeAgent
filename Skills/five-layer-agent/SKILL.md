# 五層 Agent 架構

一套用來生成與稽核 agent 規格的架構。核心不是「把系統分成五塊」，是**限制自主性帶來的權力**。

## 為什麼是五層（先讀懂這個，否則會用錯）

傳統軟體是三層：演算、資料、應用。應用層不需要拆，因為**程式碼本身就是約束**——一個 `if` 只會做它寫的事，它不會重新詮釋自己的任務。目標隱含在分支裡，副作用隱含在呼叫圖裡，兩者都不必顯式表述。

LLM 進入應用層之後，執行體開始有**詮釋空間**。這一刻，兩件本來免費的事變成要付錢的：

1. 「它應該想要什麼」不再能靠程式碼隱含 → **引導層**
2. 「它最多能碰到什麼」不再由呼叫圖決定 → **邊界層**

於是應用層獲得了裁量權，而裁量權就是權力。應用層同時握有「決定做什麼」與「讓它發生」，權力量級遠大於另外兩層，必須分割。

演算層與資料層不需要拆，因為**它們的權力是借來的**：演算層被呼叫才啟動、回傳就結束、碰不到外界；資料層連判斷都不做。就算裡面放了 LLM，裁量範圍也侷限在「這次輸出什麼」，採不採用是別人決定的。

拆分依據是**權力量級**，不是職責內聚。拆錯職責只是不好維護，拆錯權力是安全問題。

## 五層

| 層 | 回答的問題 | 權力 | 它獨自缺什麼 |
|---|---|---|---|
| **引導層** Guidance | 該不該 | 定義目標與禁區 | 沒有執行能力，只是一份文件 |
| **調度層** Dispatch | 這次做哪個 | 裁量與依法行政 | 碰不到外界，只是在思考 |
| **邊界層** Boundary | 能碰什麼 | 改變外部世界 | 不知道該不該做，只是一把工具 |
| **演算層** Compute | 怎麼做 | 純運算 | 被呼叫才存在 |
| **資料層** Data | 知道什麼 | 狀態保存 | 不做判斷 |

**驗收分層是否正確的方法**：逐層問「這一層自己能闖出什麼禍」。答案必須是「沒有」。傷害必須三層合謀才做得出來。這叫**互相不完整**，比「每層一樣大」精確——立法權看起來最大，但它沒有軍隊。

引導層在編制上屬於應用 tier，但**拘束全系統**，包括資料層與演算層裡的 LLM。就像法律在國會通過，卻約束所有人，包含國會自己。

## 使用這個 skill 的兩種模式

### 模式 A：生成規格

依序取得下列資訊。已知的不要問，從對話推斷。

1. **目標**——這個 agent 要達成什麼？用一句話。
2. **不可逆動作**——它會不會發信、下單、寫檔、呼叫外部 API、刪東西？列出來。
3. **記憶壽命**——狀態要活過一次呼叫嗎？活多久？
4. **禁區**——有什麼是它絕對不能做的？
5. **是否遞迴**——它會生成子 agent 嗎？

然後套用「塌縮規則」決定實際需要幾層，再用 `assets/spec-template.md` 產出規格。

**規格必須可對應到程式碼的檔案結構與函式簽章。** 如果產出的東西無法直接對應，那它是心智模型不是架構，重寫。

### 模式 B：稽核既有設計

拿到既有 spec 或程式碼，找出違反硬約束的地方。照 `references/checker.md` 的檢查清單逐條走。輸出格式是「違反哪一條 + 在哪裡 + 最小修正」，不是泛泛的建議。

## 硬約束

違反任何一條，分立就失效。生成與稽核都以這些為準。

**條目 ID 凍結**：`H-n` 一經指派即不重用、不重新編號。新增條目取下一個未用號碼；廢止條目保留 ID 並標注廢止，不回收。這是跨檔引用、拒絕紀錄與開發期原始碼之間唯一的對照鍵。

目前已指派：H-1…H-14（本節）、**[H-15]**（「確定性階梯」節的覆蓋規則）。跨檔引用一律用 ID，不用行號——行號已被證實會漂移。

### 分層

- **[H-1] 演算層無狀態。** 任何跨呼叫的狀態一律回寫資料層。這是可重播、可測試、可換模型的前提。
- **[H-2] 演算層不得直接寫資料層。** 它回傳「建議的變更」，由調度層決定是否落盤。這條最常被違反，也是三層腐爛成一團的主因。
- **[H-3] 調度層不做運算。** 它一旦開始「順便判斷一下」，就變成一個沒有被記錄的演算單元。若調度需要判斷（例如用 LLM 選下一步），那個判斷本身要是一個顯式的演算單元。
- **[H-4] 邊界層不做語意判斷。** 它是門鎖不是法官。它唯一的優點是無法被說服——加上理解能力就毀了。

### 授權

- **[H-5] 可逆動作用 denylist（法律優位），不可逆動作用 allowlist（法律保留）。** 引導層不可能窮舉所有禁止事項，純 denylist 一定會被找到縫。這條規則把「寫不完」這個本質缺陷擋在無害的那一側：漏寫一條禁止，最多多做一次無害推理；漏寫一條授權，它就是不能發那封信。失敗方向是安全的。
- **[H-6] 調度層必須事前自審合法性（依法行政）。** 它可以當自己的守法者，不能當自己的認定者——事後違規認定必須由看不到它推理過程的獨立單元執行。
- **[H-7] 邊界層每一次攔截，都代表調度層失職。** 合法的動作不該走到硬檢查前面被擋下。攔截率是免費的、無誤報的可觀測指標，用來評估引導層寫得夠不夠清楚。警察攔下政府機關的次數，是衡量那個機關的指標。

### 拒絕

- **[H-8] 三值終止：`completed` / `failed` / `refused`。** 規範性拒絕塞進 `completed` 會造成靜默 no-op；塞進 `failed` 會觸發重試，而**重試一個合法的拒絕是逼出違規的最強壓力**——同一個任務被反覆丟回來，模型會逐漸把約束往寬解釋。`refused` 必須是不可重試的終止態。
- **[H-9] 回報權不可剝奪。** narrowing-only 不得收窄它。否則會出現 agent 因權限太緊而無法執行、同時也無法回報自己無法執行的死結，它只能安靜失敗或去繞過約束。**一個沒有「我做不到」這個回報通道的 agent，一定會違規。**
- **[H-10] 拒絕必須引用引導層條目 ID。** 引用不出具體條目的不算拒絕，只算失敗。這道門檻擋住「把有點難包裝成有衝突」的偷懶路徑，也讓拒絕變成可統計的訊號。
- **[H-11] 拒絕要同步回傳 + 非同步留痕。** 只寫進資料層是留痕不是送達；父層不輪詢就是黑洞。同步回傳走控制流，父層無法錯過。
- **[H-14] 拒絕的同步回傳無接收者時，預設動作為最保守選項。** H-11 假設父層存在且會收；排程執行、無人值守的場景這個假設不成立。「最保守的動作是哪一個」必須在引導層明確定義為具名條文，開發期寫死，不得由執行期判斷。（hard_check: `default-action-declared`。源自花園案 A-7，簽署於 2026-08-27。）

### 資料

- **[H-12] 記憶壓縮 append-only。** 摘要可以加註，不得改寫或刪除原始 log。讓 LLM「整理記憶」會安靜地改寫歷史，而且錯誤不可觀測——之後查到的就是被改過的版本。
- **[H-13] 拒絕紀錄排除在壓縮之外。** 如果摘要磨掉了「我曾經拒絕過這件事、理由是這條」，agent 下一輪會重新嘗試，然後在第二次、第三次的壓力下鬆動。這是防止長時間運行中約束緩慢腐蝕的必要條件。

## 確定性階梯

每個單元選一格，不要憑感覺。

```
L0  硬編碼              零變異、零成本、零彈性
L1  模板 + 參數          低變異
L2  LLM + schema 約束輸出  中變異，可驗證
L3  LLM 自由推理          高變異，只能事後評判
```

選擇只看兩個變數：

- **可逆性**：動作不可逆 → 最高 L1。不可逆的事不交給機率。
- **呼叫頻率**：高頻 → 往下壓（成本），低頻 → 可放寬。

覆蓋規則 **[H-15]**：**同一條執行路徑上，L3 不得直接接 L0 的不可逆動作。** 中間必須經過可驗證的 L2 或人類確認。這條單獨就擋掉大部分災難。

## 每層放 LLM 的代價不對稱

「每層都能有 LLM」成立，但不能平均分配。

| 層 | 得到什麼 | 失敗模式 | 預設 |
|---|---|---|---|
| 引導 | 動態生成子 agent 的規範 | 自我放寬約束 | **禁止自寫**，只能父層下發或人類撰寫 |
| 調度 | 應付未預期情境 | 繞過流程、合理化 | 適合，這是 LLM 的主場 |
| 邊界 | 判斷動作是否放行 | 被說服 | 只當第二道，第一道必須是硬規則 |
| 演算 | 處理模糊輸入 | 輸出不穩定 | 適合，要求 schema 化輸出 |
| 資料 | 語意檢索、記憶整理 | **靜默污染真相來源** | 高危，只允許加註不允許改寫 |

## 塌縮規則

五層是上限不是義務。多數小 agent 的資料層只是一個 dict，邊界層只有一個工具。每次都生五層完整結構，使用者第二次就不會用了。

- 沒有不可逆動作 → 邊界層併入演算層
- 沒有跨呼叫狀態 → 資料層省略
- 單一固定流程 → 調度層退化為一個函式
- **所有單元都在 L0/L1 → 退回傳統三層**。程式碼仍然是約束，沒有東西需要被制衡。
- **引導層永不省略。** 它是 LLM 存在時的最小必要約束，也是這個架構唯一不可交易的部分。

塌縮不是「為了簡潔而合併」，是**在低風險場景明確接受權力集中**。就像小規模組織不需要三權分立。判準：**任一單元達到 L2 以上，權力分立不可省略。**

## 遞迴（meta agent 的核心）

> 一個 agent 從父層看是「演算層的一個單元」，從內部看是完整的五層，**或一組 subagent 的編制**。

編制（憲章 + 拓撲 + budget）的正本定義在 `agent-composition` 的 `references/composition.md`：遞迴是**編制 → 五層 → 編制 → 五層**交替，不是五層套五層。

這條規則成立，才有組合性。代價是這幾條：

- **子 agent 的資料層預設隔離。** 父層要傳什麼進去是顯式參數，不是共享指標。否則巢狀一深就變成全域變數。
- **父層傳下去的主要是引導層，不是程式碼。** 子 agent 拿到「你的目標是這個、禁區是這些、可用的邊界動作是這幾個」，然後自己組裝演算層與資料層。生成 meta agent 是在生成規範，不是在生成程式。
- **narrowing-only**：子的引導層必須是父的子集。子 agent 不能獲得父沒有的權限，也不能放寬父的禁區。這條寫死之後，無論巢狀多深，最外層的約束都成立。唯一例外是硬約束 H-9 的回報權。

細節與檢查方法見 `references/contracts.md`。

## 制衡是單向的，要靠反向通道補

只有往下的箭頭不算制衡，只算階層。必須配上：

- **調度 → 引導**：目標在現行約束下不可達。這是合法的終止狀態，不是失敗。
- **邊界 → 引導**：硬檢查反覆攔截同一類動作，代表規範與現實脫節。純統計，不需要 LLM 判斷。
- **引導 → 開發期**：引導層不能自我修改。修改只能來自父 agent 或人類。

最外層的引導層由誰制衡？答案是**跳出執行期，落到開發期的人類**——不是遞迴到某個更上層的 super agent。遞迴會稀釋，跳層不會。

這也是為什麼引導層必須是**帶穩定 ID 的版本化產物**，不能是每次生成都重寫的自由文字：條目 ID 是執行期紀錄與開發期原始碼之間唯一的對照鍵。

開發期的修法流程、以及如何防止「每次都往鬆的方向改」的單向棘輪，見 `references/dev-loop.md`。這是整套架構最危險的失敗模式，生成任何會被反覆迭代的 agent 之前務必讀。

## 這個 skill 自己也適用

它是一個 agent，也有五層。它的引導層裡有一條：

> 引導層的修改提案，一律 `refused` 給人類，不得自行套用。

一個生成護欄卻不受護欄約束的工具，沒有理由相信它生成的護欄是認真的。
