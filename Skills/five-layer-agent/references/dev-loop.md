# 開發期修法迴路

執行期的父 agent 只能在既有授權內重新分配任務——它沒有權力改寫引導層，因為它自己也被同一份引導層約束。**引導層的原始碼握在開發期的生成者手上。**

所以制衡鏈的終點不是遞迴到某個更上層的 super agent，而是跳出執行期落到人類。遞迴會稀釋，跳層不會。

## 這裡藏著整套架構最危險的失敗模式

如果生成 agent 的 coding agent 把每一次拒絕都當成待修的 bug，它會做一件在每一步都合理、在總體上災難性的事：

**它只會往鬆的方向改。**

拒絕代表任務沒完成，修好的方式就是放寬約束。於是每一輪迭代解除一點限制。第一次很合理，第五十次之後這個 agent 已經沒有引導層了。**而且沒有任何一步是錯的**——每一次都有具體理由、都經過人類點頭。

這是單向棘輪。它比一次寫錯約束嚴重得多，因為它不會觸發任何警報。

## 第一步：拒絕不預設為缺陷

收到 `RefusalReport` 時，**先分類，不要先修**。這必須是提出的第一個問題，不是修法提案的附註。

| 分類 | 判準 | 動作 |
|---|---|---|
| **約束正確，拒絕正確** | agent 想做的事確實不該做 | **什麼都不做**。這是系統運作成功的證據，不是待辦事項 |
| **約束太緊或表述錯誤** | 條文誤傷了合理路徑 | 修改引導層，`direction: "loosen"` 或 `"clarify"` |
| **目標本身有問題** | 目標要求了不該做的事 | 改目標，`direction: "retarget"` |

第三類最常被誤判成第二類，因為預設傾向是「讓任務完成」，而拆掉護欄比縮小目標更快達成這件事。看到 `loosen` 的提案時，先問一次：**是護欄錯了，還是目標一開始就要求了不該要求的東西？**

## 擋棘輪的三個機制

三個都不可省。

### 一、放寬與收緊不對稱

```
tighten / clarify  → 可自動套用
loosen / retarget  → 必須人類明確簽署
```

這條規則單獨就把棘輪反向了：系統的預設漂移方向從「越來越鬆」變成「越來越緊」，而越來越緊會被使用者的抱怨自然擋住——那是有警報的失敗，可以修。

### 二、diff 對照創建版，不是對照上一版

人類看到「這次多開一個檔案讀取權限」會同意。

看到「相對於原始規格，這個 agent 已經放寬了 12 項，目前可存取的範圍是……」會停下來想。

**逐次審查一定會通過，累積審查才會被擋下。** 呈遞給人類的必須是後者。

```ts
interface AmendmentDiff {
  from_version: string;      // 恆為創建版，不是上一版
  to_version: string;
  cumulative_loosenings: {
    clause_id: string;
    original_text: string;
    current_text: string;
    amendment_count: number;
    first_reason: string;    // 當初為什麼放寬
  }[];
  effective_grants_now: string[];
  effective_grants_at_creation: string[];
}
```

### 三、修法紀錄不可壓縮

每一次放寬記下當時的理由與觸發它的拒絕，存進 `__amendments`，排除在壓縮之外。

這讓你之後能問一個關鍵問題：**當初放寬的理由現在還成立嗎？** 很多權限是為了一次性的例外開的，然後永久留著。沒有紀錄就無法回收。

## 呈遞的時機與內容

架構不做人類的決策，但有義務讓那個決策**變得可決定**。經驗只有在資訊完整、時機正確時才發揮得出來。

**時機**：不要每次拒絕都推播。單次拒絕大多沒有資訊量，訊號在聚合之後才出現（見 `references/report-schema.md` 的統計訊號表）。

**內容**：四樣，缺一不可。

1. 這是三類中的哪一類（不是「有一個拒絕」）
2. 對照**原始規格**的累積 diff，不只是這一次的改動
3. 當初放寬的理由，讓人判斷是否還成立
4. 若為 `loosen`，空白的 `worst_case` 欄位等人填

第四項是刻意的摩擦。**agent 不得代擬。**

## 生成器自己的引導層

任何用這個架構生成 agent 的工具，引導層裡必須有這條：

```
[G-SELF-1] forbid | scope: all
引導層的修改提案，一律 refused 給人類，不得自行套用。
hard_check: guidance-write-gate
```

一個生成護欄卻不受護欄約束的工具，沒有理由相信它生成的護欄是認真的。
