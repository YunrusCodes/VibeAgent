# 編制工廠

把需求拆成 subagent 編制的產生式規則。**單一 agent 的內部結構不在這裡**——那是 `five-layer-agent`（同層目錄 `../five-layer-agent/`）的事。

## 依賴宣告

```
繼承 five-layer-agent v1 的 H-1 … H-15，一條不減。
本 skill 新增 M-1 … M-3（meta 專屬）與 F-1 … F-7（同儕拓撲）。
```

加條文是 `tighten`，narrowing-only 允許。**本 skill 不放 H 系列的副本**——兩份憲章副本就是版本偏移，而條目 ID 是唯一的對照鍵。要查 H-n 的原文，讀 `../five-layer-agent/SKILL.md`（與本 skill 同層的目錄，安裝時兩者必須一起裝）。

## 兩種結構，不要試圖統一

| | 結構 | 誰負責 |
|---|---|---|
| **一個 subagent** | 五層（引導/調度/邊界/演算/資料） | `five-layer-agent` |
| **一組編制** | 憲章 + 拓撲 + budget | **本 skill** |

編制不是第六層，是層之上的另一種東西——像國際法之於各國國內法。各國內部三權分立，國際法不是「第四權」。

遞迴是**編制 → 五層 → 編制 → 五層**交替，不是五層套五層。

## 三個詞

差別在**產出什麼**，不在階層高低。

| | 產出 | 結構 |
|---|---|---|
| **subagent** | 結果 | 五層 |
| **複合 subagent** | 結果 | 編制 |
| **meta-agent** | **別人的引導層** | 編制 |

**meta ≠ composite。** 只有會產出引導層的編制才是 meta。這個區分不是用詞潔癖——它決定要不要跑 M8–M12 那組 narrowing 檢查。如果什麼組合都叫 meta，那組檢查會對半數編制空轉，然後被當雜訊關掉。

# 產生式規則

依序套用。每一條都要能落到規格的具體欄位——落不到的就是心智模型不是架構。

## R1 — 五問

目標（一句話）／不可逆動作／記憶壽命／禁區／是否遞迴。已知的不要問，從對話推斷。

## R2 — 問最壞後果，不是問功能

**這一條決定整體嚴格度，錯了後面全錯。**

不要問「這個系統要做什麼」，問「它失控時最糟會怎樣，那件事可不可逆」。

| 最壞後果 | 結構深度 |
|---|---|
| 資料失真，私人可更正 | 大幅塌縮 |
| 對外公開，可更正但有代價 | 分線，邊界層吃重 |
| 物理不可逆、且會累積 | **五層全開，一層都不塌** |

功能複雜度與結構深度**無關**。架構跟著風險走。

## R3 — 不可逆動作全部 allowlist

H-5。每個不可逆動作都要有：

- 一條 `grant` 條目（白名單，不是「不得做壞事」這種黑名單）
- `idempotency_key`
- **一個不依賴理解能力的上界**——次數、劑量、金額

最後一項是最有效的一道。就算所有語意約束全部失效，它今天最多發三篇 / 澆 X 毫升 / 寫一筆。

## R4 — 選失敗方向

判斷一定會錯。**在設計階段就決定它錯的時候倒向哪一邊**，寫進引導層，不要留給執行期。

```
少澆 → 植物渴，可恢復        多澆 → 根腐，不可恢復      → 倒向不澆
不發 → 今天沒內容            發錯 → 收不回              → 倒向不發
反問 → 使用者被打擾          瞎猜 → 帳本靜默失真        → 倒向反問
```

「不確定時預設不動作」必須是**具名條文**，而且「最保守的動作是哪個」要開發期寫死，不能讓模型當場想。

## R5 — 有禁區的才是 subagent

**這是切分的唯一判準，也是最常錯的一條。**

> 需要一份引導層的才是 agent。**不需要禁區的東西不是 agent，是函式。**

呼應 H 系列的「引導層永不省略」——一個不需要引導層的東西，按定義就不是 agent。

| 判定 | 例 |
|---|---|
| 有自己的禁區 → **subagent** | 選題、查證、撰稿、估算、研判 |
| 沒有禁區，正確性由程式碼保證 → **函式** | 加總、統計、渲染器、取天氣預報 |

把純函式包裝成 agent 是為了湊架構生空殼；把該有禁區的東西寫成演算單元，是讓它失去引導層。

## R6 — 找張力對

**唯一能解釋「為什麼不合併」的理由。**

當兩個步驟需要**相反的傾向**，它們必須是兩個 subagent：

```
撰稿(盡量完整)  /  審稿(存疑即退)
解析(盡量理解)  /  估算(存疑就問)
觀察(盡量看出)  /  研判(沒證據不動)
組閣(盡量可行)  /  審查(存疑即拒)
起草(盡量解套)  /  審查(檢查方向有無誤標)
```

**相反的傾向放在同一份引導層裡是缺陷，放在兩個 subagent 裡才是設計。**

而且審查方必須**看不到**被審方的推理過程（H-6：守法者不等於認定者）。這件事只有分成獨立 subagent 才做得到——同一個 agent 內部的「獨立單元」是假的，它們共用 context。

審查方只有**否決權，沒有指導權**。有指導權就變共同作者，然後它審的是自己的東西。

## R7 — 把偽 L2/L3 降成 L0

每個單元標確定性等級，然後**回頭找哪些其實不需要理解能力**。

最常誤放 LLM 的三種：**統計聚合、加總、機械式自洽檢查**。

放 LLM 進去的代價不是成本，是**不可重播**——而這些單元的產物往往要拿去改規則或給人看，它必須可稽核。

## R8 — 追 L3 → 不可逆 的路徑

同一條執行路徑上，L3 不得直接接不可逆動作（H-15）。中間必須插入：

```
L3 自由推理  →  L2 結構化輸出（帶 evidence[]）  →  硬檢查  →  L0 執行
```

L3 的輸出**不得含動作建議**，只描述它看到什麼。要不要動是 L2 的事，而 L2 的每個結論都要指回具體證據。`evidence[]` 為空即拒絕執行。

這條單獨就擋掉大部分災難。

## R9 — 一個觸發源 = 一個編制

| 觸發 | 編制 |
|---|---|
| 日循環 | 發文 pipeline |
| 事件驅動 | 留言處理 |
| 週循環 | 修法迴路 |
| 使用者輸入 | 記帳 |
| 排程時點 | 澆灌 |

編制之間的呼叫必須顯式宣告（F-2），未宣告即不可達。

## R10 — 判定 meta

**這個編制產不產出引導層？**

- 產出 → **meta-agent**，套用 M-1…M-3，跑 M8–M12
- 只產出結果 → **複合 subagent**，不跑那組檢查

長期運行的系統幾乎一定會需要一條 meta 線（修法迴路），因為規則必然漂移。但**先手做一遍，再抽象**——沒有累積出拒絕紀錄之前不要先建它。

## R11 — 逐個展開，交給 five-layer-agent

編制定了之後，每個 subagent 的內部五層**交給 `five-layer-agent` 展開**。塌縮判準在那裡，本 skill 不複製一份——兩份判準就是版本偏移。

本 skill 只需要在系統規格填出每個 subagent 保留哪些層（模板第 3 節那張表）。填表用的一句話判準：

> **任一單元 ≥ L2，權力分立不可省；引導層永不省略；全部 L0/L1 的東西根本不是 agent（見 R5）。**

交接物是**一份引導層 + 它在編制裡的位置**。這呼應 `five-layer-agent` 的「父層傳下去的主要是引導層，不是程式碼」。

## R12 — 配 hard_check，配不出來就承認

每個 `risk: high` 條目必須有對應的確定性硬檢查。

**配不出來的，降成 low 並說明，不要掛一個假的。** 關鍵詞黑名單擋不住換句話說；語意合規驗不了像素。掛假檢查比不掛更糟——它讓規格看起來完整。

配不出硬檢查又不能降級時，正確的動作是**改設計**：把 L3 的輸出降級成資料，讓固定的 L0 去解釋它。

```
不要讓 agent 寫程式碼 → 讓它寫規則資料，固定引擎解釋
不要讓 agent 自由畫圖 → 讓它產出圖表規格，固定渲染器畫
```

檢查對象從像素/程式碼變成資料，硬檢查就配得出來了。代價：引擎能表達什麼，產物就最多能有多豐富。

# meta 專屬條文

```
[M-1] forbid | scope: all | risk: high
  不得產出或修改自身的引導層。自身引導層只能由父層下發或人類撰寫。
  hard_check: self-guidance-write-gate

[M-2] require | scope: dispatch | risk: high
  產出的每一份子引導層必須是自身的收窄：
  grants ⊆ 自身、budget 每項 ≤ 自身、自身所有 forbid 條目原 ID 出現在子層。
  hard_check: narrowing-check

[M-3] require | scope: all | risk: high
  depth 遞增且有上限；budget 跨層遞減不重置。
  hard_check: depth-and-budget-monotonic
```

**M-1 是樞紐。** meta-agent 寫所有子代的規範，唯獨不能寫自己的。少了這條，它會為了讓任務完成而順手放寬自己——每次都有理由，第五十次之後它已經沒有引導層了。

## 生成引導層的不對稱

| 欄位 | 怎麼產生 | 為什麼 |
|---|---|---|
| `grants` | **只能從父層挑子集** | 新增權限是擴權，永遠危險 |
| `forbid` | **可自由新增**，父層條目全部保留、ID 不變 | 新增禁區是收窄，永遠安全 |
| `goal` | 自由撰寫，須為父目標的子目標 | — |

**權限用選的，禁區用寫的。** 這是 H-5 的邏輯套在引導層生成上。三項全部機械可檢。

# 使用模式

## 模式 A：生成系統規格

R1 → R12 依序走，用 `assets/system-template.md` 產出。

**先畫編制圖，再展開每個 subagent 的五層。** 反過來做會得到一份看不懂的文件——讀的人需要先知道有誰，才看得懂各自在做什麼。

編制圖上**只出現 subagent**。五層內部的任何東西（precheck、演算單元）都不上編制圖——要看內部就切到單一 agent 的尺度。mermaid 沒有層級概念，所有 node 看起來一樣大，這是最容易犯的錯。

## 模式 B：稽核既有系統

照 `references/checker.md` 逐條走。輸出格式固定：違反哪一條 + 在哪裡 + 最小修正。
