# 編制

## 從父層看是一個單元，從內部看是什麼

`five-layer-agent` 說：一個 agent 從父層看是「演算層的一個單元」，從內部看是完整的五層。

**這句話少了一半。** 從內部看有兩種可能：

```
完整的五層          → 它是一個 subagent
一組 subagent 的編制 → 它是複合 subagent 或 meta-agent
```

所以遞迴是**編制 → 五層 → 編制 → 五層**交替，不是五層套五層。

編制不是第六層。層是權力的切分（誰能決定、誰能執行、誰能記住），編制是**單位之間的關係**（誰能呼叫誰、共用什麼預算、誰替誰立法）。像國際法之於各國國內法——各國內部三權分立，國際法不是「第四權」。

| | 結構 | 內容 |
|---|---|---|
| subagent | 五層 | 引導 / 調度 / 邊界 / 演算 / 資料 |
| 編制 | 憲章 + 拓撲 + budget | 誰在裡面、誰能呼叫誰、共用多少額度 |

## 三種東西

差別在**產出什麼**，不在階層高低。

| | 產出 | 結構 |
|---|---|---|
| **subagent** | 結果 | 五層 |
| **複合 subagent** | 結果 | 編制 |
| **meta-agent** | **別人的引導層** | 編制 |

「meta」不是階層高低，是輸出型別。產出規範的才叫 meta。

**由多個 subagent 組成 ≠ meta。** 如果 composite 就算 meta，這個詞不做任何工作，而代價很具體：meta 這個標籤決定要不要跑 narrowing 檢查（M8–M12）。什麼組合都叫 meta，那組檢查就會對半數編制空轉，很快被當成雜訊關掉。

# 切分：什麼是一個 subagent

## 判準：有沒有自己的禁區

> **需要一份引導層的才是 agent。不需要禁區的東西不是 agent，是函式。**

這直接來自「引導層永不省略」——一個不需要引導層的東西，按定義就不是 agent。

| 判定 | 三題裡的例子 |
|---|---|
| **有自己的禁區 → subagent** | 選題（不得選醫療題目）、估算（不得偽裝估算為測量）、觀察（不得含動作建議） |
| **沒有禁區 → 函式** | 加總、統計彙整、圖表渲染器、取天氣預報 |

兩個方向的錯誤都有代價：

- **把純函式包裝成 agent** → 空殼。它的引導層會是空的，或塞一些「要算對」這種不是禁區的話
- **把該有禁區的寫成演算單元** → 那幾條禁區沒有地方掛，它失去引導層

## 判準二：張力對

**唯一能解釋「為什麼不合併」的理由。**

當兩個步驟需要**相反的傾向**，它們必須是兩個 subagent：

| 寬 | 嚴 | 出自 |
|---|---|---|
| 撰稿：盡量完整可讀 | 審稿：存疑即退 | 科普帳號 |
| 解析：盡量理解使用者的意思 | 估算：存疑就問 | 記帳 |
| 觀察：盡量看出問題 | 研判：沒證據不動作 | 花園 |
| 組閣：盡量產出可行的陣容 | 審查：存疑即拒 | 留言處理 |
| 起草：盡量解套 | 審查：檢查方向有無誤標 | 修法迴路 |

**相反的傾向放在同一份引導層裡是缺陷，放在兩個 subagent 裡才是設計。**

同一個形狀在三題裡出現五次。看到「一個單位同時負責生成與檢驗」就是紅旗。

## 為什麼分開才有效

兩個附帶條件，少一個就白拆：

**一、審查方看不到被審方的推理過程。**
H-6：守法者不等於認定者。同一個 agent 內部的「獨立單元」是假的——它們共用 context，審查看得到起草為什麼那樣寫，然後就會被說服。只有分成獨立 subagent，這件事才是結構性的。

**二、審查方只有否決權，沒有指導權。**
一旦它能說「應該改成這樣」，它就是共同作者，**然後它審的是自己的東西**。獨立性消失，而獨立性是它存在的唯一理由。

# 編制的切分

**一個觸發源 = 一個編制。**

| 觸發 | 編制 | 出自 |
|---|---|---|
| 日循環 | 發文 pipeline | 科普帳號 |
| 事件驅動 | 留言處理 | 科普帳號 |
| 週循環 | 修法迴路 | 科普帳號 |
| 使用者輸入 | 記帳 | 記帳 |
| 排程時點 | 澆灌 | 花園 |

編制之間的呼叫必須顯式宣告（F-2）。

## 判定 meta

**這個編制產不產出引導層？**

| 編制 | 產出 | 判定 |
|---|---|---|
| 發文 pipeline | 文章 | 複合 subagent |
| 留言處理 | **handler 的引導層** | **meta** |
| 修法迴路 | **引導層修正提案** | **meta** |
| 記帳 | 帳目 | 複合 subagent |
| 澆灌 | 澆水施肥 | 複合 subagent |

一個系統只要**有任何一條線產出引導層**，整體就是 meta-agent。

科普帳號整體是 meta，因為②③會產出引導層——**這個系統能長出自己沒有預先寫好的規範**。記帳與花園不會，所以是複合 subagent。

長期運行的系統幾乎一定會需要一條 meta 線（修法迴路），因為規則必然漂移。但**先手做一遍，再抽象**——沒有累積出拒絕紀錄之前不要先建它，那時候你不知道要改什麼。
