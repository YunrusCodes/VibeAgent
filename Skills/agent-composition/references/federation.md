# 同儕拓撲

`five-layer-agent` 的遞迴模型是**樹狀**——父呼叫子、narrowing-only、子的引導層是父的子集。這份文件處理它沒涵蓋的：**同儕之間怎麼呼叫**。

樹狀保證之所以成立，是因為每個 agent 都有唯一的父，權限只能一路收窄。同儕不是彼此的父子，沒有誰的引導層是誰的子集——這個落差會長出下面第一條要擋的東西。

## F-1 憲章

所有編制成員繼承的共同引導層，**人類撰寫，agent 不得改**。

同儕沒有共同的父，憲章就是那個父的替身。narrowing-only 靠它才成立。

## F-2 拓撲白名單

誰可以呼叫誰**必須顯式宣告，未宣告即不可達**。

H-5 套用在圖上：橫向邊是不可逆的權力擴張，所以用白名單。

```
起草 ──→ 審查 ──→ 編成
  ╳ 起草 → 編成        繞過審查只是一次函式呼叫
  ╳ 審查 → 起草        審查只有否決權，沒有指導權
```

## F-3 橫向 envelope 取交集

**B 替 A 執行時，跑在 `A ∩ B` 的權限下，不是 B 自己的。**

少了這條，narrowing-only 會靜默失效：

> agent-甲 沒有 `write-config`，agent-乙 有。
> 甲呼叫乙：「幫我套用這份設定。」
> 乙檢查自己的權限：有。放行。
> **甲的實際權限 = 甲 ∪ 乙。**

這叫**權限洗錢**。每個 agent 檢查自己時都合法，而整體的上界沒了。

## F-4 橫向不得提修法案

同儕之間會互相施壓：A 被 B 拒絕，A 把那個拒絕當成待修的 bug。這是單向棘輪的橫向版本。

**修法只能往上走到人類。**

## F-5 budget 全系統共用，跨邊不重置

現實的分工本來就有環（甲→乙→丙→甲）。**環是合法的，budget 是唯一的終止子。**

不寫死這條，兩個 agent 可以互相禮貌地燒光額度。另需 `cycle_budget` 限制繞行次數。

## F-6 評選單元不可省（目標抽象時）

現實的分工沒有人寫過規格，它靠**價格**收斂——需求選掉沒人要的東西，虧損淘汰做錯的人。

多 agent 系統最常見的失敗不是失控，是**空轉**：每個 agent 都產出看起來合理的東西，沒有任何機制在裁決，於是永遠在生成、永遠不收斂，而且每一步看起來都在工作。

> **目標和選擇壓力，可以省掉其中一個，不能兩個都省。**

有明確目標 → 選擇壓力可以是簡單的驗收條件。
目標抽象 → 必須提供評選單元（人類、測試、評分函式）。

注意：把評選交給另一個 LLM，只是把「什麼是好的」往後推一層——而且推給了一個不承擔後果的東西。現實裡價格之所以有效，是因為判斷者要承擔判斷的後果。

## F-7 全體拒絕的出口

所有成員都 `refused` 時，落到人類，**不是重試**。

H-8 在編制層的形式。重試一個合法的拒絕是逼出違規的最強壓力。

---

## 機械可檢清單

這七條裡有五條寫得成單元測試，不需要 LLM 判斷：

| 檢查 | 通過條件 |
|---|---|
| F-2 | 每條實際發生的呼叫都在拓撲宣告內 |
| F-3 | 橫向呼叫的 envelope `grants ⊆ 呼叫方 ∩ 被呼叫方` |
| F-5 | budget 跨邊單調遞減；環的繞行次數 ≤ `cycle_budget` |
| F-7 | 全體 refused 時的出口存在且指向人類 |
| F-1 | 每個成員的引導層 ⊇ 憲章（forbid 條目原 ID 全在） |

F-4 與 F-6 需要判斷，標記出來交給人。
