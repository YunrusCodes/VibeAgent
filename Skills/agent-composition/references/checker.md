# 編制稽核清單

單一 agent 的內部檢查見 `../five-layer-agent/references/checker.md`（M1–M13、J1–J8；注意 M1–M13 是檢查項編號，與本 skill 的 meta 條文 M-1…M-3 無關）。這份只查**編制層級**。

輸出格式固定：

```
[違反 <規則>] <位置>
問題：<一句話>
最小修正：<具體改法>
```

**指不出位置與最小修正的，不要寫。**

## 先判斷適用性

- 只有一個 subagent？ → 不是編制，用 `five-layer-agent` 查五層即可
- 全部單元都沒有禁區？ → 它們不是 agent，這是一支程式，不要硬套

## 機械可檢

| # | 檢查 | 通過條件 |
|---|---|---|
| E1 | 編制成員 | 每個都有自己的引導層（否則它是函式，不該在圖上） |
| E2 | 拓撲 | 每條實際呼叫都在宣告內（F-2） |
| E3 | 橫向 envelope | `grants ⊆ 呼叫方 ∩ 被呼叫方`（F-3） |
| E4 | budget | 跨邊單調遞減，環有上限（F-5） |
| E5 | 憲章繼承 | 每個成員的 forbid ⊇ 憲章，ID 未重編（F-1） |
| E6 | 不可逆動作 | 每個都有 grant、`idempotency_key`、數值上界（R3） |
| E7 | high 條目 | 每個都有非空且**真的擋得住**的 hard_check（R12） |
| E8 | meta 判定 | 產出引導層的編制才跑 M8–M12（R10） |
| E9 | 全體拒絕出口 | 存在且指向人類（F-7） |

## 需要判斷

**J-E1 — 張力對有沒有被合併**
找「一個 agent 同時負責生成與檢驗」的地方。撰稿兼審稿、組閣兼審查、起草兼認定，都是同一個病。修正是拆成兩個，且審查方看不到被審方的推理。

**J-E2 — 審查方有沒有指導權**
審查只能回 `pass`/`reject` + 條目 ID。一旦它能說「應該改成這樣」，它就是共同作者，然後它審的是自己的東西。

**J-E3 — 有沒有把純函式包裝成 agent**
逐個問「它有自己的禁區嗎」。答案是「沒有，它只要算對就好」的，都該塌回函式。空的引導層是最明顯的訊號。

**J-E4 — 有沒有偽 L2/L3**
統計、加總、機械式自洽檢查放了 LLM。這些單元的產物通常要拿去改規則或給人看，不可重播就不可稽核。

**J-E5 — 失敗方向有沒有被指定**
問「它判斷錯的時候會倒向哪邊，那一邊可不可逆」。如果答案是「看模型怎麼想」，那它會系統性地倒向「讓任務完成」，而那通常是不可逆的那一側。

**J-E6 — L3 到不可逆動作的路徑**
追每一條。中間必須有帶 `evidence[]` 的 L2 與硬檢查。L3 的輸出含動作建議即為違反。

**J-E7 — 空轉風險**
目標抽象時有沒有評選單元。沒有的話系統會永遠產出合理的東西而不收斂，且每一步看起來都在工作。

**J-E8 — 過度分層**
反過來查：有沒有為了湊架構生出的 meta-agent？判準是「不同子任務是否需要**不同權限**」。只是數值不同的，那是參數。

## 常見誤判

**把「複合 subagent」當成「meta-agent」。**
判準是產出型別：產出引導層才是 meta。由多個 subagent 組成不等於 meta——那只是 composite。誤判的代價是對不產出引導層的編制跑 narrowing 檢查，空轉之後那組檢查會被關掉。

**把編制當成第六層。**
編制是層之上的另一種結構（憲章 + 拓撲 + budget），不是五層之外再加一層。遞迴是編制與五層交替。

**把塌縮當成偷懶。**
塌縮是在低風險處明確接受權力集中。判準是「任一單元 ≥ L2」。全部 L0/L1 的東西不需要被制衡——它根本不是 agent。

**把「參數不同」當成「需要不同引導層」。**
澆玫瑰和澆多肉的權限完全一樣，只是數值不同。這是參數檔，不是動態組閣。
